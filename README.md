# Phishing Simulator

Учебный стенд для проведения тестовых фишинговых кампаний внутри организации, с вомзожностью:

- рассылки писем пользователям из CSV с персональными ссылками/токенами,
- фиксацией переходов в локальной БД SQLite,
- уведомления в Telegram о каждом переходе.

## Состав

Работает на docker и состоит из следующих компонентов:
| Компонент | Роль | Порт |
| ---------------------------- | ------------------------------------------------------------------------------------- | ------------- |
| **Nginx** | отдаёт страницу-уведомление, зеркалит запросы в трекер на Python | 8084 |
| **Tracker** (Python/FastAPI) | фиксирует переходы в SQLite и шлёт уведомления в Telegram | 8000 (внутр.) |
| **Mailer** (Python) | CLI-инструмент для рассылки писем: считывание почтовых ящиков из CSV → генерация токенов → отправка писем через указанный SMTP-сервер | запуск через CLI |
| **SQLite** | БД переходов (`tracker/data/tracker.db`) и выданных токенов (`mailer/data/tokens.db`) | — |
| **MailPit** | локальный SMTP-сервер для демо, письма смотрятся в веб-интерфейсе | 8025 |

## Быстрый старт

```bash
git clone https://github.com/<ваш-логин>/phish-simulator.git
cd phish-simulator
docker compose up -d
```

Поднимаются nginx (8084), tracker и mailpit (8025). Mailer в фоне не работает — это CLI-инструмент, запускается на шаге рассылки.

### Демонстрация на локальном почтовом сервере

1. **Рассылка** — письма через встроенный MailPit (веб-морда на 8025):
   ```bash
   docker compose run --rm mailer --smtp-host mailpit --smtp-port 1025 --from-addr security@test.ru --base-url <IP машины со стендом>
   ```
2. **Просмотр писем** — откройте `http://<IP>:8025`. В списке — отправленные письма с фишинговой ссылке в кнопке «Подтвердить учётную запись».
3. **Клик по ссылке** — открывается страница-уведомление, переход фиксируется.
4. **Проверка записи в БД:**
   ```bash
   docker compose exec tracker python -c "import sqlite3; [print(r) for r in sqlite3.connect('/app/data/tracker.db').execute('SELECT * FROM clicks')]"
   ```
5. **(опционально) Telegram-уведомления** — см. раздел ниже.

Ссылка из письма ведёт на `http://<IP>:8084/?email=...&token=...`.

### Рассылка на реальные адреса

Вместо mailpit есть возможность указать реальный SMTP-сервер:

```bash
# Отправка писем на внутренний почтовый сервер без шифрования (порт 25) / relay
docker compose run --rm mailer --smtp-host <IP-адрес/DNS вашего почтового сервера> --base-url <ip-адрес-устройства с phish-simulator> --from-add <имя почтового ящика>@<DNS вашего почтового сервера>

# Отправка писем на внешние адреса через ваш почтовый сервер: STARTTLS (587) или SMTPS (465)
docker compose run --rm mailer --smtp-host <IP-адрес/DNS вашего почтового сервера> --base-url <ip-адрес-устройства с phish-simulator> --from-add <имя почтового ящика>@<DNS вашего почтового сервера> --smtp-port 587 --tls
docker compose run --rm mailer --smtp-host <IP-адрес/DNS вашего почтового сервера> --base-url <ip-адрес-устройства с phish-simulator> --from-add <имя почтового ящика>@<DNS вашего почтового сервера> --smtp-port 465 --ssl
```

Основные флаги mailer:

| Флаг              | Назначение                                                                        |
| ----------------- | --------------------------------------------------------------------------------- |
| `--smtp-host`     | адрес SMTP-сервера (обязательный)                                                 |
| `--smtp-port`     | порт (по умолчанию 25)                                                            |
| `--from-addr`     | отправитель (по умолчанию `security@<домен smtp-host>`)                           |
| `--base-url`      | IP/DNS хоста вашего стенда для генерации ссылок                                   |
| `--template`      | HTML-шаблон из `mailer/data/` (если там лежит один - он выбирается автоматически) |
| `--csv`           | файл со списком получателей (по умолчанию `./mailer/data/users.csv`)              |
| `--tls` / `--ssl` | STARTTLS / SMTPS                                                                  |
| `--dry-run`       | показать ссылки без отправки писем                                                |

Список получателей: CSV с колонками `email`, `first_name`, `last_name` (пример — `mailer/data/users.csv`) для автоматической подстановки данных в поля письма: {{.FirstName}} {{.LastName}}.

## Telegram-уведомления

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`), получите его токен.
2. Напишите боту любое сообщение и узнайте свой `chat_id`: откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` → `"chat":{"id":...}`.
3. В `docker-compose.yml` раскомментируйте строки в сервисе `tracker` и подставьте значения.
4. Обновите `docker compose up -d` — теперь после каждого перехода бот пришлёт сообщение вида:

```
Фишинговый переход
Email: ivan@test.ru
IP: 10.10.10.15
Дата: 2026-08-15 10:15
Token: 8f34d2
```

### Ключевые решения

**Nginx mirror для трекинга.** Ссылки в письмах — «чистые» (`?email=...&token=...`), без служебного пути вида `/track`. Nginx отдаёт страницу мгновенно, а копию запроса отправляет трекеру в фоне (`mirror`). Пользователь ничего не замечает; прямой доступ к `/mirror_track` извне закрыт конфигурацией nginx (`internal`).

**Tracker не возвращает страницу.** Трекер — только API: принял параметры, записал в БД, отправил уведомление. Это разделяет ответственность: nginx отвечает за UX, tracker — за данные. Плюс трекер недоступен из интернета (не публикует порты).

**SQLite.** Две отдельные БД: `tracker.db` — переходы (кто, откуда, когда), `tokens.db` — выданные токены (для сопоставления кампаний). Разделение данных рассылки и кликов упрощает аудит и сброс кампаний.

**Mailer — CLI, а не постоянно работающий сервис.** Рассылка — ручная операция (запустил → отправил → получил отчёт), смысла держать поднятым контейнер - нет. Поэтому mailer вынесен в compose-профиль `cli`: `docker compose up -d` поднимает только нужные для работы стенда сервисы, а рассылка — явное действие администратора. Токены генерируются `uuid4().hex[:8]` и фиксируются в `tokens.db`.

**MailPit для демо.** Это встроенный SMTP-сервер со своим веб-интерфейсом. Нужен для демонстрации работы, при его использовании наружу ничего не отправляется. Для запуска реальных кампаний нужно использовать внешние почтовые сервера (Postfix и тд) указав информацию через флаги `--smtp-host/--tls/--ssl`. Для отправки внутри компании достаточно указать адрес smtp сервера и его порт `--smtp-host/--smtp-port`.

**Дедупликация кликов (5 сек).** Иногда Nginx mirror при разрыве соединения может отправить запрос дважды → в БД появлялись дубли, поэтому повторный клик с тем же (email, token, ip) в окне 5 секунд игнорируется; поздние повторные переходы записываются как отдельные события. Окно можно изменить в коде tracker main.py изменив параметр DEDUP_WINDOW_SEC.

**IP клиента.** Nginx пробрасывает реальный адрес через `X-Forwarded-For`. На Linux-хосте записывается настоящий IP; на Docker в Windows входящий трафик проходит через NAT и будет виден только адрес шлюза (172.x.x.x) — платформенное ограничение.

**Токен и email в URL.** Токен уникален для каждого письма — по нему видно, какое именно письмо «кликнули».

```
phish-simulator/
├── docker-compose.yml      # поднятие всех сервисов, одной командой
├── README.md
├── .gitignore

│   ├── nginx.conf          # mirror-конфиг трекинга + размещение страницы уведомления

│   ├── Dockerfile
│   ├── main.py             # FastAPI: /track → SQLite + Telegram
│   ├── requirements.txt
│   └── data/               # tracker.db (создаётся при старте)
├── mailer/
│   ├── Dockerfile
│   ├── main.py             # CLI-рассылка (argparse, SMTP, токены)
│   ├── requirements.txt
│   └── data/
│       ├── letter.html     # шаблон письма (подстановки {{.FirstName}}, {.LastName}}, {{.URL}}), можно подкладывать свои шаблоны писем.
│       └── users.csv       # CSV-список получателей (поля: email, first_name, last_name)
└── docs/
```
